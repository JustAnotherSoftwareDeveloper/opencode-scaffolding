# Lesson Writer Skill (SKILL.md)

---
**Frontmatter**
```yaml
name: lesson-writer
description: Drafts a structured documentation lesson (`.md`) for each orchestration session that captures core lessons, failures, recoveries, and reusable insights.
```
---

## Overview
This skill is invoked after meaningful harness work, identified failures, or noteworthy recoveries. It creates a dedicated Markdown lesson file that can be referenced by the orchestrator as part of its knowledge base.

## File Location & Naming Convention
Lesson files live at:
```
.lessons/<unix-timestamp>-slug.md
```
The `<unix-timestamp>` is generated from the session start time (seconds since epoch). The `slug` is derived from a concise, human‑readable title of the lesson.

## Lesson Frontmatter Fields
Each lesson must contain the following YAML front matter at the top:
```yaml
artifact_type: lesson
schema_version: 1
id: <unique-uuid>
elapsed_at: <ISO8601 timestamp when lesson created>
source_plan: <file-path-to-the-proposal or plan that triggered this lesson>
source_state: <file-path-or-reference to the state contract used for validation>
```
Additional optional fields may be added later (e.g., `tags`, `prerequisites`).

## Required Sections
1. **Context** – Brief description of what is being documented, including:
   * Session ID / Unix timestamp.
   * Source proposal and state contract used.
   * High‑level objectives of the lesson.
2. **What Happened** – Detailed account of events that led to a failure or noteworthy insight (e.g., error stack, observed behavior, why it matters).
3. **Lesson** – Core takeaways:
   * Best practices applied.
   * Code snippets or configuration changes made.
   * Why the approach succeeded / what could be improved in future runs.
4. **Future Guidance** – Recommendations for handling similar scenarios next time, including:
   * Checklist items to verify before execution.
   * Potential edge‑cases to test.
5. **Applies To** – Session identifiers (plan ID, state contract path) and any related orchestrations where this lesson is relevant.

## Validation Checklist
- [ ] Frontmatter includes `name`, `description`, required YAML fields (`artifact_type`, `schema_version`, `id`, `elapsed_at`, `source_plan`, `source_state`).
- [ ] File name follows `.lessons/<timestamp>-<slug>.md` naming convention.
- [ ] No secret information (API keys, private tokens) is included in the lesson markdown.
- [ ] All code snippets are trimmed to relevant parts; any secrets or noise removed.
- [ ] Each required section (`Context`, `What Happened`, `Lesson`, `Future Guidance`, `Applies To`) exists and is present in ordered sequence.
- [ ] The `source_plan` points to the actual proposal file (`.proposals/...`).
- [ ] The `elapsed_at` timestamp matches the session start time generated by a reliable clock.
