## Initial Plan Authoring

- After collecting documentation skills, reconcile the exact collector record named `markdown-writing-guide`, with `class: documentation` and its collector-winning `SKILL.md` path. Load it before task authoring, then explicitly read `markdown-writing-guide -> reference/writing-quality.md`. Block if the record is absent or mismatched, or if the required load fails.
- Treat the guide as passive context for plan-writer, not as an operation. Write task fields for the person who will execute or review the task.
- Apply the guide only to compatible, substantive prose authored or substantively revised in packet `summary` and task fields `purpose`, `context`, `executionInstructions`, `verification`, and `expectedOutput`. Preserve each field's existing schema and task-contract meaning. In particular, `summary` remains a one-paragraph account of the request's goal, scope, and constraints, and each `purpose` remains a single actionable, self-contained sentence describing one task result. Keep source-derived, verifiable substance and constraints. The guide does not authorize changing task boundaries, evidence distinctions, or source fidelity.
- A specialized artifact format or operation class does not, by itself, exclude the guide. Use the guide as a complement only where it is compatible with that artifact's local contract and writing guidance.
- Keep `tasks.md` as deterministic rendering of validated task JSON. Do not use the guide to revise the renderer's fixed layout or mechanically rendered values. The packet/task-field author remains responsible for substantive prose.

## Canonical Packet Execution

- While executing a canonical packet, do not recollect or self-load the guide. Use it only if the packet declares it and it is already loaded. Before relying on its guidance, read `markdown-writing-guide -> reference/writing-quality.md`.
- Never load an undeclared skill. Preserve the packet's existing owner, evidence, and format contracts.

## Assigning The Guide To Generated Tasks

- During the existing post-boundary assignment, select the exact collector-winning `markdown-writing-guide` record as `class: documentation` when the task requires substantive Markdown or Markdown-like prose to be authored or revised and the guide adds compatible value. Include prose within a specialized artifact when the guide complements, rather than replaces, that artifact's local writing guidance and contract. A specialized format or operation class alone is not a reason to omit the guide. Fixed field names and positions do not turn authored prose into rendering; the operation remains responsible for that prose.
- Do not select it for deterministic rendering of existing fixed-field data into Markdown, mechanical edits that author or revise no substantive prose, path-only `.md` work, or non-prose tasks. Decide from the prose the task asks to author or revise, not its extension.
- Reconcile the record's exact name, class, and path. Block an applicable assignment if the record is absent or mismatched; do not substitute another skill.
- The guide is never an operation owner and counts toward the existing maximum of two documentation assignments. Do not assign it automatically merely because plan-writer loaded it for its own authoring. Select it only when the generated task meets the prose condition above and it fits the existing assignment limit; keep exactly one operation owner and no more than two materially relevant documentation skills.

## Bounded Correction

- Before a substantive prose correction, load the guide in a direct workflow and read its writing-quality reference. In packet execution, use it only when declared and already loaded, then read that reference.
- Keep corrections within the exact finding-authorized fields. The guide does not grant broader edit authority.
