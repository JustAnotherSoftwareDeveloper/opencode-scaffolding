# Selection Evaluation

Evaluate the complete profile, not isolated words. Use exact expected skill sets when
the selection contract requires them.

1. Test an owned request and a faithful paraphrase. The profile must be selected.
2. Change the distinguishing input or output to a nearest neighbor. The neighbor must
   be selected instead.
3. Test a request that combines two genuinely required concerns. Select both owners
   when both are needed.
4. Test owner, support, and reference requests separately. Do not make a reference
   profile appear to own execution.
5. Test a misleading file path and a low-overlap wording. Meaning, not path or shared
   nouns, must determine selection.
6. Test an unrelated request and a request with no applicable skill. Do not force a
   broad-tag match or fallback.

Record failures as edits to the smallest tag, condition, or description that caused the
confusion. Re-run the neighboring cases after every edit. Validate support names only
against the complete discovered inventory; class filtering must not hide a valid
support target.
