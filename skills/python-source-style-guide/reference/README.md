# Documentation Files

Choose the topic that matches the source-level decision. The hub preserves the former
guide path and holds the shared scope and precedence; the five topic pages contain the
examples and qualifications for their own decisions.

- [Compatibility hub](python-source-style-guide.md) — shared scope, evidence limits,
  precedence, ownership boundaries, and routes for existing consumers.
- [Names and imports](names-and-imports.md) — How do I name or import a symbol without
  mistaking a convention for permission to change an interface?
- [Readable layout and control flow](readable-layout-and-control-flow.md) — How can I
  make dense code easier to scan while preserving its values and branches?
- [Functions, classes, and state](functions-classes-and-state.md) — Where should
  behavior and state live, and how do I avoid accidental behavior changes while
  decomposing code?
- [Comments and docstrings](comments-and-docstrings.md) — What belongs in a comment or
  docstring, and how should an established documentation format be preserved?
- [Annotations and typing idioms](annotations-and-typing-idioms.md) — How can I express
  useful type intent without implying runtime validation or exceeding supported Python
  versions?
