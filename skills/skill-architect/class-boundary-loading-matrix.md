# Class Boundary and Loading Matrix

## Purpose

Describe the approved class boundaries and the direction in which passive reference
context may be associated with active work.

## Applicability

Applies to ordinary operation and delegated execution, inline exact-declaration
execution, and the scoped planning collector workflow.

## Non-goals

This document does not execute a load, define a procedure, resolve assignments,
validate runtime behavior, or authorize tools, writes, delegation, or completion.

## Authority source

The authority is the local [class taxonomy](class-taxonomy.md) and [class boundary
rules](class-boundary-rules.md), read with the indexed five-class architecture.

## Scope

Operations and delegated workers may receive relevant documentation as passive
context under their applicable contract. Ordinary execution does not treat planning
material as an executable dependency. Inline execution retains exact declared-skill
semantics. The planning collector may provide planning context separately from
operation/documentation assignments. Collector-winning names, classes, and paths
remain authoritative; similarity does not repair a mismatch.

## Evidence status

The asymmetric direction and collector separation are approved and source-supported.
Interactive runtime enforcement is not claimed by this passive reference.

## Shared passive-contract verification

This concern is coupled to the indexed scope and contains reference context only.
It grants no execution authority, implicit loading, tool use, file change, delegation,
or completion authority.
