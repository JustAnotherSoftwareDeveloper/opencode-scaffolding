# Problem Framing

## Define The Problem

- State the observed situation without embedding a preferred solution.
- Identify the decision, outcome, or question that requires analysis.
- Define the affected system, actors, locations, and time horizon.
- Separate symptoms from the underlying problem statement.

## Establish Boundaries

- List in-scope components, decisions, and stakeholders.
- List exclusions that prevent scope expansion.
- Record fixed constraints, dependencies, and non-negotiable requirements.
- Define measurable success criteria and failure conditions.

## Resolve Ambiguity

- Define terms that admit multiple interpretations.
- Surface assumptions embedded in the request.
- Ask for the smallest missing fact that changes the scope or success criterion.
- Produce a bounded problem statement before evaluating solutions.
