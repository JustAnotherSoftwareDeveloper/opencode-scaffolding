## Scope

### In scope

- **Included scope:** Proposal workspace navigation and section ownership for the canonical
  numbered decision files. [Proposal format](../../reference/proposal-format.md)

### Out of scope

- **Exclusions:** Implementation commands, assignments, estimates, owners, and runbook steps in
  decision files. The separate `10-implementation.md` overview owns that detail.
  [Workspace contract](../../reference/workspace-contract.md)

### Success boundary

- **Success:** `PROPOSAL.md` provides stable navigation, each canonical section remains
  independently readable in its own file, and implementation detail remains separate.
  [Proposal format](../../reference/proposal-format.md)

The boundary is causal: separating navigation and section ownership from implementation detail keeps partial review focused on the decision while preserving a dedicated implementation overview. [Proposal format](../../reference/proposal-format.md)
