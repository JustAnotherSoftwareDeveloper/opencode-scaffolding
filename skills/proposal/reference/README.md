# Proposal reference

- [Proposal format](./proposal-format.md) defines the one-document section order,
  question model, metadata, evidence, and review boundary.
- [Writing style](./writing-style.md) defines concise engineering prose,
  information density, technical scanability, and human review.
- [Workspace contract](./workspace-contract.md) defines deterministic workspace,
  source, path, manifest, table-of-contents, and publication integrity.
- [Implementation format](./implementation-format.md) defines concrete in-document
  `Implementation Details` grouped by affected technical area.
- [Section rationale](./section-rationale.md) explains the engineering review path
  and when optional technical subsections are justified.
- [Examples](../examples/README.md) demonstrate short, standard, and complex
  one-document proposals and separate deterministic checks from human review.

These references govern newly authored or deliberately revised proposals. Historical
`.proposals/` workspaces remain immutable evidence and are not active format aliases.
