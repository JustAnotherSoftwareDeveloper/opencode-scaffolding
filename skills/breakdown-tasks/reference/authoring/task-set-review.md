# Task-Set Review

Use this review after drafting tasks and before skill assignment. Structural
validation checks packet shape; this review checks whether the breakdown makes sense.

## Checks

- **Coverage:** Completing all tasks satisfies the requested outcome. Every requested
   or necessary result appears once, and every exclusion is deliberate.
- **One result per task:** No task still contains separate questions, decisions,
   changes, or deliverables. A final document or shared file does not hide separate
   results.
- **Aggressive boundaries:** Separate discovery, research, analysis, decisions,
   authoring, implementation, verification, and reporting whenever each can produce a
   concise handoff or completion decision. Split every uncertain boundary.
- **Usable handoffs:** Every dependency names the predecessor result, consumer
   use, and readiness condition. File handoffs appear in the consumer's read set.
- **Aligned completion:** Each task's purpose, expected output, instructions, and
   verification address the same result.
- **Stable assignment boundary:** Skills have not influenced task count or changed
   a task's scope.

If a check fails, return the affected work to the decomposition method, revise the
breakdown, and run the complete review again. Do not repair a bad boundary by changing
only its title or metadata. Do not merge tasks merely to avoid fine granularity.
